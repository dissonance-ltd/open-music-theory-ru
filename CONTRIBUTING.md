# Как работать над переводом

Цель ближайшего этапа — полный, согласованный русский черновик выбранной редакции OMT2 с учётом всех примеров и заданий. Независимая музыкально-теоретическая рецензия и локализация внешних материалов учитываются отдельно. Публикация на Pages сама по себе не означает редакционной готовности.

## Перед началом

1. Прочитайте [политику перевода](docs/translation-policy.md), [правила обозначений](src/translation-notes.md) и [глоссарий](glossary/terminology.yml).
2. Проверьте текущую ветку `main`, открытые PR и [трекер глав](docs/chapter-tracker.md). Продолжайте существующую работу, не создавая второй перевод той же главы.
3. Выберите связанный по теме пакет: обычно 1–3 главы. Сложная глава с анализом, нотными примерами или интерактивными упражнениями может составлять отдельный PR.
4. Отметьте пакет в трекере, указав исполнителя и ветку/PR. Копируйте [шаблон проверки главы](docs/chapter-checklist.md) в `docs/reviews/<source-id>.md` для каждой главы. Пропуск проверки обозначайте явно, а не пустой галочкой без пояснений.

## Последовательность работы

### 1. Подготовить источник

Рабочая редакция — **Nebraska Fall 2023**. Канонический VIVA остаётся отдельной задачей сравнения. Не смешивайте редакции незаметно: альтернативный источник для недоступного примера записывается отдельно с объяснением соответствия.

Добавьте выбранные страницы в `upstream/sources.json`; импортируйте сначала в отдельный каталог и сравните:

```bash
uv sync --locked
uv run --locked python scripts/import_upstream.py --output /tmp/omt-candidate
uv run --locked python scripts/diff_upstream.py upstream/manifest.json /tmp/omt-candidate/manifest.json
```

Код завершения `1` у сравнения означает обнаруженные изменения, добавления или удаления; это результат для анализа, а не разрешение автоматически принять источник. Проверьте также изменение `catalog.json`: скрипт сравнения манифестов не проверяет оглавление. После сверки перенесите принятые снимки и манифест. Не меняйте хеш привязки существующего перевода, пока не сверите его с изменившимся текстом.

До перевода перечислите в файле проверки разделы, выводы, определения, примеры, таблицы, сноски, упражнения и медиа. Для каждого элемента укажите расположение и план обработки. Нулевое количество означает «проверено, отсутствует»; неизвестное — «не оценено». У встроенного упражнения проверьте содержимое, а не только наличие iframe. Если доступа нет, зафиксируйте конкретный пробел.

### 2. Перевести

Сохраняйте полноту объяснения и естественный русский язык. Пользуйтесь действующим глоссарием; новые термины сначала добавляйте как `candidate`. Дополнения и исправления источника обозначайте как «Примечание переводчиков». Сохраните атрибуцию, лицензию и явную пометку черновика.

Иллюстрации и ссылки связывайте с источником через `upstream/assets.json` и файл проверки. В `upstream/translations.json` укажите точный хеш нормализованного оригинала, путь перевода, `status: draft`, `reviewed_by: null` и изменения относительно источника. Добавьте главу в оглавление и замените соответствующие внешние перекрёстные ссылки локальными.

### 3. Сверить с оригиналом отдельным проходом

Откройте оригинал и готовый перевод рядом и последовательно проверьте все элементы инвентаря. Ищите пропуски, добавленные утверждения, изменение оговорок, отрицаний, последовательности действий, букв нот, интервалов, чисел и подписей. Совпадение числа абзацев не является критерием.

Запишите найденные расхождения и их исправления. Если проход выполнялся с помощью ИИ, укажите это, дату, инструмент/модель, если известны, и проверенные ревизии. Не называйте самопроверку независимой рецензией. У нового черновика перед статусом «готов к рассмотрению» должен быть записан результат сверки; у исторических глав отсутствие записи остаётся видимым долгом.

### 4. Проверить терминологию и чтение

Проверьте новые термины и их употребление в предыдущих главах. В первую очередь разбирайте различия русской и американской традиций, гармонические функции, метр, энгармонию, нумерацию октав и неоднозначные определения. Обычный редакторский проход можно выполнить самостоятельно; независимую человеческую проверку отмечайте только после фактического получения её результата.

Прочитайте главу целиком по-русски. Проверьте собранную страницу: последовательность примеров, размер нотных рисунков, таблицы, сноски, ссылки и возможность чтения на узком экране. Если визуальная проверка не выполнена, запишите это; HTML-проверки не заменяют её.

### 5. Проверить и передать пакет

Для содержательных изменений запускайте существующие проверки из корня репозитория:

```bash
uv run --locked python -m unittest discover -s tests -v
uv run --locked python scripts/render_glossary.py --check
uv run --locked python scripts/check_book.py
mdbook build
uv run --locked python scripts/check_book.py --built
```

Используется mdBook 0.4.52. После правки YAML-глоссария сначала выполните `uv run --locked python scripts/render_glossary.py`. Проверки подтверждают техническую согласованность, но не точность перевода, работоспособность внешних ресурсов или доступность всех интерактивных заданий. Для изменений только служебной документации достаточно проверить соответствующие ссылки и согласованность записей; CI всё равно выполняет общий набор проверок.

Обновите трекер, запись проверки главы, сведения об атрибуции и видимый статус книги. В PR кратко укажите пакет, новые термины, отличия от источника, результаты проверок и конкретные вопросы рецензенту. Используйте [шаблон PR](.github/PULL_REQUEST_TEMPLATE.md). Не заставляйте рецензента восстанавливать решения из истории чата.

## Изменение Python-инструментов

Архитектура, обоснование зависимостей и совместимость описаны в [scripts/README.md](scripts/README.md).
Для кода установите `uv sync --locked`, затем
запустите `uv run --locked ruff check scripts tests`, `uv run --locked ruff format --check scripts tests`, `uv run --locked mypy`
и тесты. Изменение нормализатора проверяйте отдельно: незаметная смена HTML меняет
хеши источников и может потребовать повторной сверки переводов. Новое поведение
и изменения схем перечисляйте в PR отдельно от перестановки кода.

## Критерии готовности

| Этап | Критерий |
|---|---|
| Готово к рассмотрению | Полный текст выбранных глав, инвентарь с судьбой каждого элемента, записанная сверка, технические проверки пройдены; ограничения перечислены |
| Можно объединить как черновик | Нет известной существенной ошибки или немаркированного пропуска, требующего исправления; спорные соответствия и непереведённые внешние материалы явно обозначены |
| Перевод в основном завершён | Весь согласованный объём имеет полные русские черновики, сверка выполнена, примеры и задания учтены, терминология согласована, проверки проходят, остаточные редакционные и медиазадачи перечислены |
| Рецензированная редакция | Для соответствующих ревизий зафиксированы независимые проверки терминологии и содержания, замечания закрыты, оставшиеся ограничения объявлены |

Человеческая рецензия не обязательна для слияния явно обозначенного черновика. Неразрешённый вопрос, меняющий смысл объяснения, блокирует готовность именно этой главы; продолжайте доступные главы и отмечайте зависимость. Слияние и публикация не должны автоматически повышать редакционный статус.

## Продолжение и изменения решений

Начинайте следующую сессию с трекера и открытых PR. Ближайший пакет: ASPN, Other Aspects of Notation, Rhythmic and Rest Values. Следующий блок — три главы о ритме и метре; до него разберите соответствия simple/compound meter. Параллельно постепенно оформляйте проверочные записи для первых шести черновиков.

Решение о термине фиксируйте в YAML-глоссарии с причиной и ссылкой на PR/рецензию. При изменении принятого соответствия найдите его употребления по репозиторию и обновите затронутые главы в том же пакете либо перечислите незакрытые места. Пересмотрите порядок работы после следующего пакета и затем после каждого тематического раздела; избегайте формальностей, не помогающих обнаружить ошибки.
